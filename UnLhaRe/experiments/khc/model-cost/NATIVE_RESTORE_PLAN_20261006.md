# 時刻復元の明示経路

native-bは実test/extract双方exit0後、KHCのmtime確認でfailed。report D0E3201E9AD388FB6B3E78A266AD8D3F587FDFC0A8AAD8DECB5E5EF66B42240Fを保持する。現src/khc/mod.rs extract_archiveはExtractOptions::default()を渡し、preserve_timestampsはfalse。mtimeが作成時刻なのは既定契約であり、製品の時刻復元バグと判断しない。単なるmtime guard除去で成功へ変えない。

archive_restore.rsは同じRelease libunlhare.rlib（SHA94A19BFD6C0AFD23D7C0453760C51B596D9BFA2C7CBE983BBFA15F6111572AC4）にthinLTO/opt3/codegen1/unwindでリンクし、実公開extract_archive_with_progressにpreserve_timestamps=trueを渡す。新しいcodec/namespace/依存/Cargo buildを作らず、既定API/CLIは変更しない。時刻復元は秒精度の元契約で全11fileを確認する。helper8MiB/compiler512MiBの既存guardを利用、EXE約1.5MiB/PDB約1.5MiBを見積る。9pairedの速度計測ではこの単発helper時間を比較勝利へ使わない。

native-cは同じ作成済み2archiveを再利用し、新規restore先でこの明示APIと7zの完全byte/mtime確認を行う。native-a/bの凍結script/reportを上書きせず、用途終了した今回restore2directoryは原入力ではないことを確認してmodule窓口で清掃し、記録を保持する。新規unit/Git/公開/他版/削除hookの操作は行わない。
