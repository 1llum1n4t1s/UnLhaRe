# CRC統一の互換性確認と限定計測

2026-10-05 Windows x64。更新後GOALはactive。7-Zipへの性能優位は未達であり、本結果は完成判定ではない。

## 実行結果

- 初回initialは測定器のPowerShell配列式 `1-$target` が配列減算として解釈され失敗。製品の符号列不一致ではない。括弧で修正し、初回reportを保持した。
- repair1は294 native呼出し、7入力×旧新×warmup1＋測定9回を完走。各符号列全byte一致、自己復号140組、相互復号14回が成功。全source/input/helper pinは前後一致した。
- 入力：empty、1 byte、repeat4KiB、all256×8、固定seed random64KiB、alice29全文、kennedy全文。固定all.group 3blockとLowHistoryOnlyは今回未実施。
- 検証前に既存30故障＋30回復E2Eとlib clippyを実行し成功。今回の計測はprocess起動・binary I/O込みで、純codec CPU測定ではない。

| 入力 | 圧縮中央値 旧→新 ms | 復号中央値 旧→新 ms |
| --- | --- | --- |
| repeat4KiB | 334.413→326.336 | 87.278→91.118 |
| all256×8 | 321.622→324.616 | 103.361→95.573 |
| random64KiB | 490.189→495.165 | 74.329→71.211 |
| alice29 | 408.783→409.578 | 140.157→141.534 |
| kennedy | 764.199→761.756 | 312.521→299.034 |

改善・悪化が混在し、min/maxも重なるため、CRC変更の安定した性能改善はこの計測では証明できない。7-Zip比較はしていない。旧強制sleep付きrunnerとの時間差をcodec高速化に数えない。
