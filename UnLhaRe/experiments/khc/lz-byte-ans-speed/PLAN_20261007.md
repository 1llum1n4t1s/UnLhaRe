# byte-CDF候補: 公開native RecordTrialを基準にしたprivate速度選別

実行前固定: 同じ11件既知データ、worker1、64MiBの全process/入力/capacity料金、同じEXE、全復元一致、warm1 + paired9、通常順と逆順を別processで実施。時間は各group内の全block API呼出しの和、byte照合は計時外。タイマー内にoutput確保、CRC、model、entropy、逆変換が含まれる。これはCLI/containerを含まない局所選別で、7-Zip最終ゲートではない。

仮説: 8bit-tree literalをbyte-CDF1intervalへ置き換えればkennedyの復号が改善するが、CDF更新費用で悪化し得る。両順でdecode median <= 同じpublic native RecordTrialなら次のencode比較へ進む。不合格なら同じ候補のparameter sweepをしない。最終採用にはencode<=1.10×RecordTrial、size frame+700<=457415B、さらに7-Zip最終ゲートが必要であり、後から緩めない。

variant生成: public native RecordTrial圧縮を1回実行、その出力がmethod2旧frame wrapperで旧method2/3の場合だけ、新ANS候補を全feeで試し、strictに短いとき選ぶ。MDL/record-codedには追加scanを行わない。新magic KAB1BLKのprivate復号、他はpublic native復号を呼ぶ。旧LZを再圧縮しない。decoder E2Eと同じsource/hashが必須。matching/search/ctx/rate/worker/grammarの値は変更しない。

前提: e2e-c最終sourceの有限/E2E合格とpin一致。allocation実注入・未見データ・Zstd・実native統合は未完で別工程。観察ヒット率や単発準備時間を速度優位へ読み替えない。

予算: source/controller24KiB、追加専用出力root8MiB（objects/EXE/64KiBreport含む）、raw/frame disk複写0、Cargo増分0、外部download0、free5GiB+出力。compiler512MiB/60s、各child64MiB/60s、suite300s、CPUquiet15%を最大60s。両raw書庫と11原文の実capacity・キャッシュframe・共通driver1MiB・ANS/modelの全額を保守的に確認する。
