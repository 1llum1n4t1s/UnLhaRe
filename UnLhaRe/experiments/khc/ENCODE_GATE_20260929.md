## 固定した判定値

通常 Release の既存比較を判定値にする。新しい中央値では置き換えない。

| | 値 |
| --- | ---: |
| KHC encode | 1001.5268 ms |
| 7-Zip encode | 574.5624 ms |
| KHC frame | 483,130 bytes |
| 7-Zip frame | 483,599 bytes |
| サイズ余裕 | 469 bytes |
| 7-Zip 時間へ届く短縮 | (1001.5268 − 574.5624) / 1001.5268 = 42.63% |

総合的に超える最低条件は、出力 ≤ 483,599 bytes かつ KHC encode < 574.5624 ms の両方である。746.931 ms は 574.5624 × 1.3 で、7-Zip より遅い。7-Zip の 1.3 倍の速さは 574.5624 / 1.3 = 441.97 ms 未満であり、今回の最低条件ではない。

## 一つだけ見た仮説

「`lz.rs:5170` の 30.71% と `bt.rs:478` の 29.96% は、Beam 展開と BT 挿入の排他時間で、その内側を約 70% 削れば 42.63% に届き、フレームは 469 bytes 以内に収まる。」

これは未検証である。flat sample は呼び出し位置への帰属で、inclusive な phase 時間でも、その行を消せば減る時間でもない。inlining を含む。二つの割合を足した 60.66% も、消せる仕事の上限として採用しない。

その誤読を上限として使っても、42.63 / 60.66 = 70.3% をその内側から消す必要がある。既存の内訳はそれより小さい。

| 既知の上限 | 総 encode 比 | サイズ |
| --- | ---: | --- |
| unique 5-byte key をただにする楽観値 | 3.93% | 未証明。一致候補の欠落があり得る |
| 空 Beam slot で frontier を省く実測 | 1.72% | 483,130 bytes のまま |
| BT frontier の理想並列 | 13.1–13.5% | 実装しない。0–2% のサイズ増は 0–約 9,663 bytes で、469 bytes を超える |
| generic PGO の実測 | 約 16.7%（別系列では 941.7668 ms 対 591.2521 ms） | 483,130 bytes。7-Zip 時間には未達 |
| Standard parser の単発 | 1001.5268 ms 比で約 55.7%（443.523 ms） | 579,558 bytes。余裕を 96,428 bytes 超える |

critical-path share は、二つの flat line からは確定できない。データの所在は [CPU profile](NORMAL_RELEASE_CPU_PROFILE_20260929.md)、[境界寄与](BOUNDARY_CENSUS_20260928.md)、`DEVELOPMENT.md` の frontier 節である。追加の実行はしていない。

速度が 574.5624 ms を下回った測定点は Standard だけであり、サイズが最低条件を外れる。サイズが 483,599 bytes 以下の測定点は、42.63% 短縮に届いていない。したがってこの仮説は、実装前の上限で不成立とする。
