## 今回の限定改善と失敗先行契約

Normalizer/Performance候補：block CRCの自前8bit/byte演算を、同じISO-HDLCパラメータの既存crc-fast Digestへ統一。
公開API/形式/revision/CRC領域順序は不変。最終化は1回、CRC欄[36..40]を除く2部分を連続update。
最強反証：同じパラメータでも分割更新誤用・実装差でCRC/wireが変わる可能性。
対策：変更前の固定helperと変更後helperを同じRAM入力へかけ、全frame byte一致と両方向cross-decodeを確認する。
空・1B・all256・反復・random・Canterbury・固定3blockを使用。既存30故障/回復も再実行。

Async候補：comparisonの64KiB readごとの強制10ms sleepは1MiB出力で少なくとも160msの要求を生む（静的回数の下界、codec実測ではない）。
新runnerは転送進捗時にsleepしない外側周回で、stdin/stderr/timeout/memoryを毎回確認する。
待機除去は測定基盤の是正であり、codec速度改善に足さない。旧速度結果との単純比較は禁止。

## opop観点と所有権

| 観点 | 担当/判定 |
| --- | --- |
| Modernizer | CRC analyst：既存依存APIで足り、依存更新非該当 |
| Normalizer | CRC analyst：同一CRC統一候補成立、親実装/実証 |
| Cleaner | CRC analyst：CRC候補と重複、独立削除なし |
| Tester | CRC/transport analysts：往復だけで不足、全frame差分/cross-decodeが必要 |
| Hardening | CRC/transport analysts：CRC検証順、入出力/RAM/時間guardとcleanupを維持 |
| Performance | 親：モデル構築/CRC費用の切り分け。倍率は計測前に主張しない |
| Async | transport analyst：進捗時sleep省略成立、workerの新runnerで実装 |
| Startup | 親：今回の配布/起動経路は変更せず、startup込みと純codecを区別する |
| Intel | 親：公式7-Zip版を確認。CRC API仕様は既存lockfileのlocal sourceで確認 |

親がsrc/khc/block/mod.rs、workerが新speed probeと新cpu-measurement-v2のplan/runnerを所有。
新unit testを書かず、公開API/実processのE2Eで確認する。旧source/helper/reportのバックアップ複製や削除は行わない。
shared Cargoの元baselineに対する残り約68MiBを維持し、新compile追加を48MiB以内見積、専用output8MiB/free5GiB。
