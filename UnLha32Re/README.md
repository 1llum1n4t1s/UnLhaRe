# UnLha32Re

完全互換版のプロジェクトは、この `UnLha32Re/` フォルダーに配置しています。
以下のビルド・試験コマンドは、このフォルダーを作業ディレクトリとして実行してください。
ソリューション名は `UnLhaRe.sln`、完全互換版の出力名は `UNLHA32RE.DLL` です。

UnLha32Re は、同梱された `UNLHA32.DLL` 3.00.0.5 の **32 ビット（x86）ABI
互換 DLL** をソースから構築するためのプロジェクトです。生成物は
`UNLHA32RE.DLL` です。従来名を固定して読み込むアプリでは、配置時に
`UNLHA32.DLL` へ名前を変更できます。

下記のデータ保護上の例外を除いた完全互換を開発目標としていますが、
現時点で全 API の全副作用を再現したという意味ではありません。
確認済み範囲と既知の差異は下記のとおりです。

## データ保護を優先する互換性の例外

利用者の明示的な選択により、次の原版のデータ消失・破損は再現しません。

| 条件 | UnLhaRe の仕様 |
| --- | --- |
| `m` が未格納・除外対象や別パスの元ファイルを削除する条件 | 書庫に格納できていない元ファイルと、処理対象でない別パスのファイルを保持する |
| `f` の列挙コールバックが既存項目を拒否した条件 | 拒否された旧項目を保持し、全件拒否でも既存書庫を消さない |
| `-jss1` の共有エラーで原版が旧項目を削除する条件 | 読めなかった入力に対応する旧項目を保持する |
| LH3 圧縮で成功を返しながら破損書庫を生成する条件 | 破損出力は再現せず、安全に復元できる LH3 書庫を生成する |
| `-jd` の巨大な予約容量で整数計算が桁あふれする条件 | 小さな必要容量への折り返しを防ぎ、展開前の空き容量確認を維持する |
| 既存書庫を置き換える途中でコピー・flush・置換に失敗する条件 | 保存先への未公開コピーが完成するまで旧書庫を保持し、失敗時は元入力も削除しない |

通常の `m` で正常に格納した元ファイルを削除する動作は互換性の対象です。
上記の例外は、他の戻り値・通知・ログや未検証機能を一律に互換と扱うものではありません。
独立した保持試験は `scripts/test-safety-exceptions.ps1` で実行できます。
保持対象の本文・CRC と拒否時の書庫バイト列を検証し、通常の移動と DLL の再利用も確認します。
同じ入力の大小文字違いは通常の移動として扱い、大小文字を区別するフォルダーの別ファイルは保持します。
容量演算の桁あふれ対策は `scripts/test-disk-space-dialogs.ps1` の安全性例外ケースで検証します。
書庫置換の保持は `scripts/test-compression-commit-failure.ps1` の候補単独36条件で検証します。
別ドライブへの分岐と各I/O失敗を注入し、旧書庫の全バイト保持・一時ファイル清掃・同一DLL再利用を確認します。
`scripts/probe-compression-commit-errors.ps1` では `a/u/f/m` の観測・最終置換拒否を
原版／候補それぞれで16観測し、観測成功時の公開行は全て一致しました。最終置換拒否では、
原版の成功（旧書庫置換後に入力削除）を安全性例外として再現せず、候補は `-1`／Win32 5 と
旧書庫・入力・一時ファイルを保持します。実ドライブ境界・電源断・UNC の一致は未検証です。

## 実装の系譜

- `sample/UnLha64x-main` のラッパー、進捗通知、公開拡張ヘッダーを出発点に、
  x86 ABI、ハンドル API、メモリ API、文字コード処理などを拡張しています。
- `sample/lha-master` と `sample/lha211_s` は UnLha64x の系譜・ベースに当たる
  LHa 実装です。本プロジェクトの圧縮・展開エンジンは、UnLha64x の Windows
  対応を含む LHa for UNIX 系コードを `third_party/lha` に収録しています。
- `sample/ulh3300_extracted/UNLHA32.DLL` は挙動比較・命令解析の比較元
  として使用し、リンクも再配布も行いません。公開構造体と宣言は同梱
  ドキュメントの `UNLHA32.H` に基づきます。

したがって、本 DLL 全体をクリーンルームの独自実装とは位置付けていません。
派生元と再配布条件は [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md) を参照して
ください。

原版 DLL の内部解析手順と確認例は [内部解析資料](docs/reverse-engineering.md) を参照してください。

## 既知の差異と未検証範囲

- 圧縮データを全入力・全組み合わせでバイト単位に一致させる検証は未完です。
  相互展開の成功は、同一の圧縮データを生成する証明ではありません。
  大きな書庫では進捗コールバックの通知回数にも差が残ります。
- `-jm5..8` の旧方式圧縮は開発中です。LH2 の 8 KiB 未満と LZS は実装済みで、
  本文・API・連続利用に加え、原版との小入力・境界条件 144 件の圧縮本文比較と
  相互展開を確認しました。全入力での圧縮バイト一致の検証は未完です。
  LZ5（`-jm8`）の圧縮も実装し、原版との本文比較・相互展開を検証中です。
  最初のパケットの未使用末尾だけは、原版の未初期化値を再現せずゼロで埋めます。
  この部分まで同じ圧縮バイト列になるという保証はありません。
  LH3（`-jm6`）と 8 KiB 以上の `-jm5` の圧縮も実装し、検証中です。
  原版 LH3 が成功を返しながら破損書庫を生成する条件は、承認済みの互換例外です。
  単一シンボルの符号木を正しく記録し、安全に復元できる書庫を生成します。
- `j` 命令の**既存連結先**が他形式の連結元を拒否する際の、原版の元パス消失・一時書庫残存は
  データ保護上の互換例外とし、元パスと旧書庫を保持します。新規・既存とも拒否・ログ・エラー・
  `-jsg0` 許可・異常後再利用を比較済みです。空項目の改名・形式変換・結合通知と、結合の終了状態も修正しました。
  既存連結先の通常進捗と中断後の旧書庫保持・再利用は修正済みです。
  COPY 時点のファイル公開状態や一時ディレクトリまで原版と一致するものではありません。
- level-2/3 のヘッダー CRC 不良に対する `l/v/t/p/e/x` と検索 API の初期復帰・途中停止は修正しました。
  `e/x` の終端異常・ヘッダー欠落、未選択項目の開始通知、開始時中断後の書庫解放も修正しています。
  展開本文の途中欠落の戻り値・ログと、非 ANSI パスを使う `UnlhaW` の共通展開経路も修正しました。
  本文 CRC 不良時の `e/x/p` の削除・続行確認、中止時のエラーと書庫解放も修正しています。
  `-gm1` では不良な展開ファイルを削除して続行し、確認画面で削除を断った場合は保持します。
  展開中断でディレクトリの日時復元が次の命令に持ち越される問題も修正しました。
  ディレクトリ項目の直後に日時・属性を反映し、古い既存フォルダーは保持します。
  `e/x/p/t` は書庫開始・項目開始・処理途中の進捗コールバック中断で `32800` を返し、
  処理済みログと日本語／英語の中断表示を保持します。`p` の中断で一時ファイルの
  ハンドルが残る問題も修正しました。終了通知の拒否は正常終了として扱います。
  `a/u/f/m` の進捗中断も終了コード・完了ログ・書庫と入力のハンドル解放を修正しました。
  連続利用時の通知日時と通知先パスも原版に合わせています。正常更新時の COPY 通知と
  中間ファイル状態、異常後の全 API・設定の組み合わせの検証は未完です。
- `pm0/pm2` の `p/t/e/x` 読み飛ばし、ANSI コマンドの文字列終端後の領域、本文 CRC、
  終端欠落と重大な本文切断は修正し、516 条件と追加 131 条件で原版と比較しました。
  全圧縮方式での復号途中の通知間隔、書庫を書き換える命令の同種エラーは未完です。
- 通常の `e/x` の上書き・特殊属性・ディレクトリ作成確認は、個別／一括の許可・スキップ、
  中断、次の命令への選択状態の初期化に対応しています。
  通常上書き・親作成の拒否後の別ファイル名入力（`-jyn0` など）にも対応しています。
  通常ファイルの空き容量不足の続行・スキップ・取消と、`-f/-jyk/-jd` の設定にも対応しています。
  出力ファイルを開けない場合は既存本文を保持してスキップし、`-jse1/2` 指定時はエラーで終了します。
  `-jse2` では日時・存在・属性による除外と通常ファイルの親作成拒否でも停止します。
  親の実作成や既存ファイルの情報取得用オープンが失敗した場合は、`-jse` に関係なく停止します。
  ファイルシステム上限による別名入力、SFX の対話経路などには未実装が残り、
  対話的なコマンド動作全体の完全互換を示すものではありません。
- 保存済みのローカル設定すべての実行時効果、日時・属性・上書きに関する残りの
  スイッチ、複数の基準ディレクトリや特殊スイッチの全組み合わせは未完です。
  圧縮時の隠し・システム属性の既定の除外、ディレクトリ通知の書き換え・拒否の全条件、一部 OS の
  通知時刻、UNIX リンクの展開・不正名の扱い、`j/y/n` の成功時ログにも差が残ります。
- `c/n/y` と既存書庫への `j` で、書庫の作成日時が失われる問題を修正しました。
  NTFS 上の通常日時と `-jsf` の上限補正・無効化・反転を比較しています。
  他の命令やファイルシステムを含む、範囲外の日時補正全体の確認は未完です。
  取得 API が返す元の FILETIME と、ディスクへ復元した日時は別々に検証しています。
- コードページで表現できない名前と、一部の特殊命令・レスポンスファイル・
  出力書式を組み合わせた経路には未検証／未対応が残ります。
  非 CP932 名の直接展開経路では、内容・読み取り専用属性とログ・エラー状態を
  分けて検証しており、成功時ログや一部のエラー状態はまだ一致していません。
  圧縮の親相対基準パス（`..\`）と、文字コードで表現できない基準パスの処理には
  差が残ります。原版の検索先と読み取り先の差も [内部解析資料](docs/reverse-engineering.md) に記載しています。
  原版の `m` には圧縮されなかった元ファイルまで削除するケースがあり、
  `f` にも列挙コールバックで拒否した旧項目を削除するケースがあります。
  `a/u/f -jss1` の共有エラー時にも、原版は対応する旧項目を削除します。
  これらのデータ消失は、利用者の選択により互換性の例外として再現しません。
  `m` の削除失敗時のエラー・入力順・後続の保持と失敗後の再利用は、試験用 DLL の
  528 条件で一致しました。通常の再帰入力 390 条件、ディレクトリー格納・置換 315 条件と
  その連続利用 48 系列も試験用 DLL で一致しています。
  初回の level-2 更新で生じていた CRC 初期化漏れは修正し、ASCII／日本語名の 80 条件を確認しました。
  `-jm0`・空入力・旧書庫の EOF による成功時の最終システムエラー値も、480 条件と連続利用
  48 系列で一致しました。ここまでの修正を合わせた試験用 DLL は追加の結合試験 2,157 条件を通過し、
  標準テストにも反映しました。後続の進捗修正を含む最新 DLL の全体再検証は未完です。
  UTF-8 モードで絵文字パスに書庫が作成されない問題は修正済みですが、
  複数項目・属性・特殊命令を組み合わせた動作全体の一致は確認できていません。
- 列挙コールバックの通常時登録では NULL・不正サイズ・不正アドレスと登録保持を比較済みです。
  圧縮時の ADD/FRESH 通知では、旧ヘッダー由来の数値情報の保持と通常の追加ファイル名を比較しています。
  全 API の連続呼び出し・異常系を組み合わせた動作の網羅は未完です。
  進捗の圧縮サイズ・CRC の保持は試験用 DLL の 864 条件で一致しましたが、
  これは COPY の一時パスや全通知順序まで一致した結果ではありません。
  既存更新の旧 BEGIN・`f` の DIRECTORY 抑止・不更新時の完了通知は 240 条件、
  進捗 OS 種別の読み取り状態を修正した level-2 更新も 96 条件で一致しました。
  復号後の進捗状態 768 条件と CRC 不良コマンド後の継続利用 160 条件も試験用 DLL で一致しました。
  COPY 時点の書庫の存在状態と一時名、ディレクトリー圧縮時の余分な BEGIN には差が残ります。
  既存書庫更新・読み取り失敗時の進捗通知も、全項目の一致は未完です。
  実行中の登録・解除は候補が拒否するため、原版との戻り値の差が残ります。
  原版で確認された登録前の解除や実行中再登録後のアクセス違反は再現しません。
  再登録直後に原版が返す未初期化メタデータも再現せず、候補はゼロ初期化します。
- 旧形式の自己解凍書庫、暗号化・パスワード関連、予約 API の全挙動は
  比較試験を完了していません。
- 比較元 DLL の非 NUL 終端 ANSI 注釈読み込みには、入力外のメモリを読む挙動が
  観測されています。その未定義動作は再現せず、読み取り範囲と終端を保証します。
- ANSI 文字列取得や UTF-8 無効の ANSI `p` 命令に容量 0 を渡すと、元 DLL はバッファ直前に書き込む場合が
  あります。候補は出力バッファを変更せず、この範囲外書き込みを再現しません。
- `OpenArchive` の NULL 入力時に返される未初期化ハンドルと、再入拒否時の
  未初期化の最終エラー値は再現しません。候補は NULL ハンドルと、再入拒否時には
  `ERROR_ALREADY_RUNNING` を返すエラー状態を使用します。
- 最初から一致しない検索で返される未初期化メタデータや、NULL 検索条件による
  原版の未初期化スタック参照も再現しません。
- 原版の再帰検索には、`*/?.txt` などで名前の終端を越えて残存バッファを読み、
  以前の名前やスタックによって結果が変わる挙動があります。候補は名前の範囲内だけを
  照合するため、この誤一致とは意図的に異なります。
- UTF-16 レスポンスに 2050 文字の検索条件を置くと原版がアクセス違反で終了する
  入力を確認しています。候補の非クラッシュ・バッファ境界検査は別枠で行い、
  この入力を両 DLL の一致確認済み範囲には含めません。
- 元 DLL と同様に、コマンド処理と設定 API はプロセス内の共有状態を使用します。

置き換え対象アプリ固有のコマンドラインとアーカイブを回帰テストへ追加してから、
本番の `UNLHA32.DLL` と差し替えることを推奨します。

## ビルド

Visual Studio 2026 の「C++ によるデスクトップ開発」が必要です。

```powershell
pwsh -NoProfile -File .\scripts\build.ps1
```

生成物は `artifacts\Release\UNLHA32RE.dll` です。

## テスト

```powershell
pwsh -NoProfile -File .\scripts\test.ps1
```

比較元 DLL が `sample\ulh3300_extracted\UNLHA32.DLL` にある場合、公開 API の
観測結果を自動比較します。

検証は専用の非表示デスクトップで実行するため、DLL の確認画面は通常の作業画面に
表示されません。分離に失敗した場合は検証を中止します。テスト単体を直接起動した場合も
自動で分離します。詳しい実行方法は [検証デスクトップ](docs/testing-desktop.md) を参照してください。

試験用ファイルの配置先は `-WorkspaceRoot "$env:TEMP\UnLhaRe-tests"` などで変更できます。
省略時はリポジトリの `build` 配下です。正常終了時は、その実行で作成した
`integration-...` フォルダーだけを削除し、配置先の親フォルダーは残します。
失敗時は調査用に生成物をその場に残し、保存先の絶対パスを表示します。

日時・存在判定は、比較元 DLL の正常終了時に採取した固定値とも照合します。
`m` の元ファイル削除だけは、固定値の書庫内容から「格納できた入力だけ削除」を
厳密な期待値として導きます。戻り値・通知・ログ・書庫内容の比較は維持します。
比較元 DLL の一時ファイル置換が不定期にアクセス拒否になる環境があるため、
この 132 ケースのライブ比較は `scripts\test.ps1 -CompareUpdatePolicyOracle`
で別途有効にできます。ライブ比較ではこのエラーも失敗とし、再試行や期待値の
変更で成功扱いにはしません。
