# ZIP リリース

リリース時は短時間の候補単独スモークを使う。原版との全比較・表示行列・長時間ストレスは、実装変更をまとめた時点や互換性調査で実行する。スモークの成功を全互換試験の成功とは扱わない。

## 通常の入口

作業ディレクトリーは `UnLha32Re/`。PowerShell 7、Visual Studio の C++ 開発環境を使う。

```powershell
# 開発中の短時間確認。ビルドとスモークだけを実行する。
pwsh -NoProfile -File .\scripts\test.ps1 -Profile Release

# 公開する変更をコミットした後、署名済み ZIP をローカルで準備する。
pwsh -NoProfile -File .\scripts\release.ps1
```

`release.ps1` は300秒のローカル予算でビルド→署名→スモーク→ZIPを直列に実行する。
スモークを通過した後の再ビルドは不要。署名は現在のユーザーの証明書ストアと Windows SDK の SignTool を使う。
署名証明書が複数ある場合は `-CertificateThumbprint` で指定する。
秘密鍵のコピーや自己署名への切り替えは行わない。証明書の認証操作は事前に済ませる。

配布版番号はルート `VERSION`、DLL の互換バージョンは `3.00.0.5` を使う。
スクリプトは版番号、Gitのブランチ、コミット、リモートを変更しない。
署名済みZIPの生成時は追跡ファイルに未コミット差分がないことが必要。
ZIPのソースは `git archive HEAD` から作り、試験用生成物や未追跡の調査ファイルを含めない。
ZIPとチェックサムは一時ディレクトリーで完成・照合し、ディレクトリーごと正式な出力先へ移す。
出力先は未作成のディレクトリーを指定する。既定の出力先が既にある場合は、空でも上書きせず `-OutputDirectory` で新しい場所を指定する。
同じ成果物を使うリリースの二重起動と、処理途中のGit HEAD変更は不合格にする。

## 検証内容と時間管理

| チェック | 判定 |
| --- | --- |
| x86 / ABI / version | x86 PE、原版130公開名＋既存拡張1件の名前と序数、互換版3.00.0.5 |
| ファイル・メモリ往復 | 65,539バイトの圧縮・展開・メモリ再圧縮を元本文と照合 |
| 列挙 | ANSI/Wide、32/64構造体の登録・解除・戻り値・件数 |
| lh0/lh1/lh5/lh6/lh7 | 実際の格納方式、元本文との全バイト一致、3メモリAPIの未使用領域・ガード、CRC |
| Unicode | 日本語とUnicode記号を含む書庫・階層名、件数、展開本文 |
| ホスト状態 | 圧縮・展開後のSIGINTハンドラー保持 |
| 競合・再利用 | 8スレッド×3反復で成功とbusyを判定 |
| データ保持 | Wide API・w64通知の更新拒否、共有違反、移動、同一DLL再利用の26件 |

プローブは正常書庫を毎回生成するため、比較元DLLや未追跡の `sample/` は不要。
`DesktopRunner` の非表示デスクトップと一時HKCUを使い、DWM監視も省略しない。
スモーク本体は既定90秒以下。時間切れは不合格とし、DWMの終了後観測と清掃を完了してから終了する。
ビルド・署名・ZIPの各工程も残り時間で制限し、失敗・期限超過時は後続工程に進まない。

実行ごとに工程の所要時間と結果を `build/release-runs/run-*/` に保存する。
`test-report.json` はDLLのSHA256、Git HEAD、プローブ・ランナーのハッシュ、環境、全チェックの結果を保持する。
ZIP生成は合格レポートと実物の署名・DLLハッシュ・HEADを照合する。失敗レポートや別のDLLには使えない。
成功した入力・展開物は清掃し、失敗時は診断用に保持する。

通常のリリースで引数なしの `test.ps1` を追加実行しない。
詳細な原版差分、全言語・全APIの交差、すべての表示応答、長時間ストレス、旧形式全般はこの経路の対象外。
それらが必要な変更の検証は開発時に対応する個別試験で行い、統合確認を明示的に実行する。

```powershell
# 長時間の原版比較が必要なときだけ実行する。
pwsh -NoProfile -File .\scripts\test.ps1 -Profile Full
```

## 公開

出力は `artifacts/releases/<VERSION>/UnLha32Re-win-x86.zip` と `.zip.sha256`。
DLLの署名と第三者告知・ソースを確認したZIPを、そのまま対象のGitHub Releaseに添付する。
公開時は対象タグ／コミットを確認し、リリースノートと両ファイルをアップロードして、取得したZIPのSHA256を照合する。
公開前後で再ビルド・全互換試験を挟まない。

300秒はローカル準備の予算で、署名のタイムスタンプ通信もこの予算に含む。時間を超えた実行は不合格になる。
証明書の本人認証は事前に済ませ、公開のGit／GitHub通信は別に計測する。
ローカル検証の実測と署名・公開の所要時間を分けて報告し、外部サービス待ちを含む成功を一律5分保証とは記載しない。
