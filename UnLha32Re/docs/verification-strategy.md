# 検証の選択と完了条件

修正中は、その変更が影響する契約を検証する。全体試験は関連する修正をまとめた時点で実行する。
試験件数を完成率と扱わず、原版との一致、安全性、未検証を別々に記録する。

## 検証の段階

| 段階 | 対象と完了条件 |
| --- | --- |
| 再現 | 問題が成立する最小入力と正常対照。修正前の差と、比較すべき出力・状態を特定する |
| 修正確認 | 最小再現と同じ原因の境界・呼び出し元。安全性例外は原版一致ではなく保持・範囲・解放を検証する |
| 関連回帰 | 対応する `test-*.ps1` の既存引数で必要な軸を選択する。省いた軸は未実行として残す |
| 統合 | 修正群が安定した時点で `scripts/test.ps1` を既定値で完走する |

全体試験を途中で停止した場合、完走した試験と中断した試験を区別する。次の試験を起動する前に停止要求を確認できるよう、手動の関連回帰は1本ずつ実行する。
異常や新しい変更がない通過済み試験は、同じ成果物で繰り返さない。
既存結果の参照時は候補・原版・プローブ・ランナーのハッシュ、入力、設定、試験スクリプト、実行環境を照合する。
一致を確認できない記録は再利用せず、影響する範囲を再検証する。自動の成功キャッシュは使わない。

## CRCダイアログの重点確認

`test-command-crc-dialogs.ps1` は既定の `-Coverage Full` で従来の全組合せを実行する。
開発中は `-Coverage Focused` で次の和集合を実行できる。

- 指定した最初の名前系列・方式・プロファイル・言語を基準に、全破損位置×全命令×全応答方針を確認する。
- 指定した最初の命令と `keep-continue`（指定されていなければ最初の方針）で、全fixture×全プロファイル×全言語を確認する。

既定軸では Full 1,600 比較に対し Focused 175 比較（原版／候補の起動3,200回→350回）。
これは重点確認であり、全ペア網羅や全組合せと同等の保証ではない。
特に基準外の名前・方式・API・言語と、別命令・停止／削除方針との交互作用は省かれる。
文字コード、ダイアログ資源、応答処理、命令分岐、破損後の状態を変更した場合は、影響する交互作用を明示指定して実行し、統合時には Full を実行する。
プロセス隔離、制限時間、ダイアログ内容、戻り値、通知、ファイル内容・属性、入力不変性の判定は両モードで共通である。
解放監査・Unicode出力先・JY応答の追加試験は、統合入口でも全件のまま維持する。

計画だけの確認は、DLLやfixtureを読み込まず、ファイルも作成しない。

```powershell
# UnLha32Re を作業ディレクトリとする。
$plan = & .\scripts\test-command-crc-dialogs.ps1 -PlanOnly -Coverage Focused
$plan | Group-Object Command, Policy | Select-Object Name, Count

# 関連するソースを変更したら先に build.ps1 を1回実行する。
# BodyDirectory は test-level3-body-errors.ps1 が生成した検証済みfixtureの場所。
$crc = @{
    TestProgram = (Resolve-Path .\artifacts\Release\CompatibilityTests.exe).Path
    RunnerPath = (Resolve-Path .\artifacts\Release\DesktopRunner.exe).Path
    Oracle = (Resolve-Path .\sample\ulh3300_extracted\UNLHA32.DLL).Path
    Candidate = (Resolve-Path .\artifacts\Release\UNLHA32RE.dll).Path
    BodyDirectory = 'C:\absolute\path\to\level3-body-errors'
    Workspace = Join-Path $PWD "build\crc-focused-$([guid]::NewGuid().ToString('N'))"
}
& .\scripts\test-command-crc-dialogs.ps1 @crc -Coverage Focused
```

`-CaseLabels` は計画の `Label` を完全一致で指定する。未知のラベルは実行前にエラーにする。
指定ラベルは Coverage による選択より優先するため、重点確認外のケースも再現できる。
元の軸・設定・入力を維持し、新しい Workspace を指定して失敗したケースだけ再実行する。
差分を検出した時点で後続ケースを停止し、差分と観測記録を保存する。

```powershell
& .\scripts\test-command-crc-dialogs.ps1 -PlanOnly `
    -CaseLabels 'japanese-jm2-crc-last-p-delete-stop-a32-1033'
```

実行先には `plan.tsv`（選択ケース）、`plan.json`（設定・入力と実行物のハッシュ）、
`observations.tsv`（比較・所要時間）、成功時だけ `summary.json` を保存する。
`Focused` / `Explicit` の成功を Full の成功へ読み替えない。未完了の計画だけでは合格としない。
単独試験の検証領域は自動削除しない。完了後に必要な結論を文書へ残し、利用中プロセス・リンク・他作業の混在を確認したうえで今回の不要物だけを削除する。
中断時は再開に必要なfixtureと失敗記録を保持し、保持理由と削除条件を引き継ぐ。

統合入口にも `-CrcDialogCoverage Focused` がある。これは標準CRCダイアログ群だけを縮小するオプションであり、
他の試験群は省略しないため短時間のスモーク試験ではない。終了メッセージにも全CRC行列を未実行と表示する。

## LZ5・LH3の本文試験と表示対照

統合入口の `-CodecPayloadDisplay Focused`（既定値）は、LZ5・LH3のメモリ展開に `-n1` を指定する。
全入力・3 API・原版／候補の読み取り・本文全バイト・戻り値・エラー・日時属性・未使用領域・両端ガードの検証を維持する。
各APIのDLL再ロード、プロセス隔離、制限時間、観測直後の出力も変更しない。圧縮処理とLH3中断回復試験は対象外である。

表示ありの対照は、同じ入力・書庫に対する全観測行を表示抑止時と比較する。代表条件は次の通り。

| 試験 | 表示あり対照の選択軸 |
| --- | --- |
| LZ5 | 書き込み側×読み取り側×実際の格納方式×空／非空入力。各組の最初の入力で3 APIを比較 |
| LH3 | 読み取り側×実際の格納方式×安全修正の有無×複数ブロックの有無。各組の最初の入力で3 APIを比較 |

書き込みAPI・圧縮プロファイル・各入力長／分布と表示の全交差は実行しない。
進捗表示、メモリAPIの表示オプション、表示に依存する状態・中断・解放処理を変更した場合や、代表対照が失敗した場合、リリース前は表示ありの全入力を実行する。
単独スクリプトの既定値は従来どおり `-PayloadDisplay Normal`。統合入口では `-CodecPayloadDisplay Normal` を指定する。
CRCの Full/Focused とは独立した設定で、終了メッセージにも両方の範囲を表示する。

```powershell
# 従来の表示あり全入力と、全CRCダイアログ行列を実行する。
pwsh -NoProfile -File .\scripts\test.ps1 -CodecPayloadDisplay Normal -CrcDialogCoverage Full
```
